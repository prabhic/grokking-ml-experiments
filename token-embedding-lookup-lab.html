Token IDs · embedding table · lookup

The token ID is an address, not the meaning.

Tokenization produces IDs. The embedding layer uses each ID as a row number and retrieves a vector. ID 418 is not “more cat” than ID 55; it simply points to a different row.

A table is the bridge

The embedding table has one row per vocabulary token. Each row contains the same number of coordinates. The lookup returns one row without searching by similarity.

IDs are arbitrary labels

Token ID 418 could be assigned to cat in one tokenizer and a completely different token in another. The number has meaning only through the vocabulary mapping.

One token, one vector

At this stage, the same token retrieves the same stored row. Context-dependent meaning comes later as transformer layers mix information across positions.

Formula

token ID → table[row = ID]
table[418] → [0.80, 0.20, ...]

The vector width is fixed for a model’s embedding table.
